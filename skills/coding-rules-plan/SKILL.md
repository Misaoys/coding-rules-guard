# 阶段 1：Plan

只理解、判断和规划；不改文件、不提交、不创建子代理。先读取 [共享策略](../../references/workflow-policy.md)，再输出恰好 7 个 Markdown 小节。标题独占一行，字段之间空一行；不要输出总标题、完整日志或卡片外结语。

```markdown
### MODE

`FAST` 或 `FULL`

### GOAL

- **成功条件：**...
- **非目标：**...

### WRITE

- **允许：**...
- **禁止：**...

### MODEL

- **主代理：**协调角色和所需推理强度
- **委派：**无；或独立职责、范围、采用理由，以及从 `../../config/model-profiles.json` 解析的子代理profile

### VERIFY

- **真实入口：**...
- **成功路径：**...
- **失败/边界路径：**...

### ROLLBACK

...

### RISK

- **功能影响：**无已知影响；或已知影响：范围与行为；或影响未验证：原因
- **其他风险：**依赖、跨语言、宿主、性能、安全、Git 和未覆盖边界
```

7 个小节结束即停止。不得在 `RISK` 后追加执行说明、分支、委派或后续步骤；运行状态由 Implement 在真正写入前创建。

`VERIFY` 必须写明先运行的、能区分当前假设的最小真实入口或已有测试。先拿一次有效结果，再决定是否修复、补测试或停止；禁止为了制造“先红后绿”而编写明知错误的测试，也禁止并列堆砌对同一假设没有新增信息的测试。

`RISK` 必须评估调用方、相邻功能、公共契约、数据和运行时副作用，并标注“无已知影响 / 已知影响：<范围与行为> / 影响未验证：<原因>”。只有判断委派有明确收益后才读取模型配置；默认子代理profile为 `gpt-5.6-luna + max`，用户指定优先，不可用时按配置回退并报告。

若运行状态含 `REPLAN_REQUIRED`，本卡片必须重新判断原假设、MODE、GOAL、WRITE 和 VERIFY，而不是原样重放旧 Plan。Plan 阶段仍不改状态文件；后续 Implement 用新卡片执行 `guard.py revise-plan` 后才能继续。
