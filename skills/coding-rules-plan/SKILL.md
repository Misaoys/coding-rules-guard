# 阶段 1：Plan

只理解、判断和规划；不改文件、不提交、不创建或调用子代理。输出必须恰好包含以下 7 个 Markdown 小节：每个字段使用三级标题、标题独占一行、内容从下一行开始，字段之间空一行。不要把多个字段挤在同一段，也不要输出总标题、项目背景、完整日志或卡片外的结语。

```markdown
### MODE

`FAST` 或 `FULL`

### GOAL

- **成功条件：**...
- **非目标：**...

### WRITE

- **允许：**...
- **禁止：**...

### MODEL

- **主聊天：**聊天名、profile/model、thinking/reasoning_effort
- **子聊天：**无；或角色、范围、profile/model、thinking/reasoning_effort

### VERIFY

- **真实入口：**...
- **成功路径：**...
- **失败/边界路径：**...

### ROLLBACK

...

### RISK

- **功能影响：**无已知影响；或已知影响：范围与行为；或影响未验证：原因
- **其他风险：**依赖、跨语言、宿主、性能、安全、Git 和未覆盖边界
```

7 个小节结束即停止。不得在 `RISK` 后追加“Plan 已完成”、自动执行说明、创建工作树/分支、调用子代理、后续步骤或其他叙述；这些内容只能由后续阶段在实际发生时报告。

`VERIFY` 必须写明先运行的、能区分当前假设的最小真实入口或已有测试。先拿一次有效结果，再决定是否修复、补测试或停止；禁止为了制造“先红后绿”而编写明知错误的测试，也禁止并列堆砌对同一假设没有新增信息的测试。

`RISK` 必须先评估本次写入对调用方、相邻功能、公共契约、数据和运行时副作用的影响。明确标注“无已知影响 / 已知影响：<范围与行为> / 影响未验证：<原因>”；已知影响和未验证边界必须在交付时如实告知，不能因本次任务未直接要求而省略。

## 模式

`FAST` 仅限只读、单文件/小范围、无公共契约变化、无宿主/发布/外部副作用、无新依赖/跨语言/物理输入的任务。只读任务到 Plan 即止且不调用子代理；有 `WRITE` 的修改任务在 Plan 完成后默认启用子代理群，再执行 `implement → verify`，仅在确有 Git/发布/正式交付时进入 deliver。

出现多文件、跨模块、CEP/AE/原生/浏览器、公共 API/协议、构建/安装/发布、安全/权限/迁移、外部服务、新依赖、跨语言、并发/性能风险或证据边界不明，必须用 `FULL`，执行四阶段链路。

## Codex 分工与模型

主聊天：`【CODEX 聊天】-【主】-<任务主题>`；子聊天：`【CODEX 聊天】-【子】-<职责>-<文件或范围>`。每个聊天必须显式写 profile、真实 model 和强度：SOL=`gpt-5.6-sol`/`xhigh`，TERRA=`gpt-5.6-terra`/`xhigh`，LUNA=`gpt-5.6-luna`/`max`。新聊天使用 `model + thinking`，多 Agent 使用 `model + reasoning_effort`。

Plan 阶段不得调用 `create_thread`/`spawn_agent`。Plan 卡片完成且 `WRITE` 非空后，默认启用子代理群；委派只能使用卡片中的职责和范围，不得跨语言、新依赖或超出范围扩张。

默认启用子代理组时，`MODEL` 必须额外记录三道门：所有子代理统一 `gpt-5.6-luna + max`；主聊天用 `gpt-5.6-sol + xhigh` 做最终审核；任何返工/复工后，再由同一 SOL/xhigh 执行复工检验。最终审核或复工检验未通过，不得进入 deliver、提交或合并。
